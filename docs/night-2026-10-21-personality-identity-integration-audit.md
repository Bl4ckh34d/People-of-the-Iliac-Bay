### P1 — New experience observers without saved personality cannot be appraised

`WorldStateStore.TryCaptureNpcExperienceAppraisal()` exits when `ReadNpcPersonality(observerId)` returns null (`src/PeopleOfTheIliacBay.Core/NpcExperienceCommit.cs:65-74`). Production profile creation occurs when a conversation snapshot captures an eligible stable speaker (`mod/Scripts/PeopleOfTheIliacBayMod.ContextSnapshot.cs:279-300`); opening native TTS has a separate first-greeting initializer (`:303-320`). Native event producers enqueue without ensuring a profile (`src/PeopleOfTheIliacBay.Core/NpcExperienceInbox.cs:382`, `NpcVitals.cs:200`, `Appointments.cs:521`). An observer who has not yet spoken can therefore retain a pending event indefinitely, so Qwen never appraises that event or updates mood, affinity, trust, fear, or resentment.

**Patch direction:** ensure deterministic profile creation at a trusted event-capture boundary using the observer's authoritative identity, seed, and background, or add an explicit no-profile appraisal contract. Do not generate personality inside a read. Define behavior for actors without stable seed and authored/quest-protected actors.

**Tests:** enqueue an event for a valid observer without a profile and prove one appraisal can be captured and committed; reopen/reload and prove all 17 axes stay stable. Also cover missing seed, protected quest actor, duplicate event, and unknown trust.

### P1 — Several legacy action/result replies skip the shared snapshot

The snapshot path gives Qwen the captured social projection (`mod/Scripts/PeopleOfTheIliacBayMod.Dialogue.cs:381-395`). The `snapshot == null` path builds older clock/weather/memory text instead (`:338-378`). `DialogueActions.cs` has result/fallback calls with no snapshot, including accepted-offer acknowledgment, stop outcomes, unavailable targets, and task/action rejection (`mod/Scripts/PeopleOfTheIliacBayMod.DialogueActions.cs:58-65, 78, 105, 340-390`). Those calls bypass captured personality, directed relationship, motivation/obligation context, and persistent-mood result handling. The accepted native action-receipt path is separate and uses `ConversationActionRenderRequest` with `ForActionVoice` (`src/PeopleOfTheIliacBay.Core/ConversationActionRenderRequest.cs:19-50`), so do not replace that receipt-bound renderer with a generic social reply.

**Patch direction:** after any native effect or result, capture a fresh successor snapshot for its spoken acknowledgment and bind it to the same actor/session. Never reuse a pre-effect snapshot after disposition, mood, or relationship changed. Keep technical failure rows out of TTS and out of personality appraisal.

**Tests:** enumerate every `SubmitSocialText` caller that supplies `knowledgeResult` or `verifiedFallback`; assert snapshot-bound context for actor-owned speech, correct current clock, and one exact mood/memory commit where persistent mood is enabled. Preserve a no-snapshot case only for an explicitly unsupported/ephemeral actor and assert unknown context rather than fabricated identity.

### P2 — Event appraisal uses a narrower context than conversation and willingness

Social Qwen replies use `ForSocialReply` with captured clock, effective disposition, directed trust/resentment/fear, all saved personality axes, commitments, mood, and the bounded actor-known motivation projection (`ConversationContextFormatter.cs:197-241, 244-280`). D3 willingness uses `ForSemanticClassifier` plus the exact original turn and typed proposal (`mod/Scripts/LocalDecisionWillingness.cs:294-328, 351-375`). D3 route selection intentionally uses `ForRouting`, an intent-only projection (`ConversationContextFormatter.cs:20-31, 48-55`; `mod/Scripts/LocalDecisionRouting.cs:41-73`).

Qwen event appraisal has a separate typed prompt. It includes the saved profile, event receipt/utterance, up to six prior observed turns, current mood/time/affinity, directed relationship with explicit `trustKnown`, and current service commitments (`NpcExperienceCommit.cs:72-115, 123-149, 152-173`; `NpcExperienceAppraisal.cs:348-422`). It does not receive the `NpcMotivationContextSnapshot` used by conversation/willingness, or the source-bound knowledge lookup. This is a narrower event-effect contract, but it can only account for the relationship, history, and duty subset explicitly passed to it. Reconcile this with the shared-projection target before claiming full cross-factor appraisal.

**Tests:** use paired event fixtures with same receipt/turn and changed stable trait, directed relationship, known trust, duty, and actor-known fact. Assert each change is present in the actual Qwen prompt and any committed output remains receipt-, revision-, and magnitude-bound. If appraisal does not need a factor, document that boundary.

### P2 — Fear/resentment update arrives after the utterance whose evidence caused it

Accepted social replies commit persistent mood before transcript append (`PeopleOfTheIliacBayMod.Dialogue.cs:436-460`). TTS then captures current mood, disposition, trust-known, fear, resentment, encounters, and all saved traits from the actor-bound store (`PeopleOfTheIliacBayMod.DialogueMemory.cs:358-389`). Observed speech enters the experience queue only as part of completed conversation handling; `TickNpcExperienceAppraisals()` is background work and pauses while Talk is open, local dialogue is busy, or TTS has pending speech (`PeopleOfTheIliacBayMod.Experiences.cs:32-65, 107-127`). Therefore the current utterance's newly appraised fear/resentment cannot affect its own wording or audio. Later speech can observe committed values.

This ordering protects one-response latency and avoids appraisal/reply races. Treat it as an explicit temporal boundary unless the approved design requires pre-reply appraisal. Do not imply same-turn fear/resentment modulation in acceptance claims.

**Tests:** make one accepted utterance produce an appraised fear/resentment delta; verify current response/audio uses pre-appraisal state, then verify next captured snapshot and TTS context use committed state. Include delayed completion, cancellation, replay, and stale-ticket cases.

## Confirmed consistency and boundaries

- **17 traits and migration:** v2 profile stores 17 axes (`NpcPersonality.cs:17-39`). `SelectedTraits` supplies 17 keys for v2 (`:41-60`); `Description()` emits all v2 values (`:104-129`). `CopyValidated()` deterministically backfills Humor, SelfEsteem, and Sensitivity from existing saved identity and seed for v1 profiles (`:64-101, 233-240`). Conversation capture uses the authoritative speaker seed and preserves quest-protected/authored actors as unknown (`PeopleOfTheIliacBayMod.ContextSnapshot.cs:279-300`). TTS delivery context is read-only and actor-person-bound (`PeopleOfTheIliacBayMod.DialogueMemory.cs:358-389`). The gap is profile availability for never-spoken event observers, not a v1 trait reroll.
- **Mood:** snapshot capture uses native game time and persistent mood when available (`PeopleOfTheIliacBayMod.ContextSnapshot.cs:145-229`). Otherwise the reply projection reports derived or unknown mood from bounded tracked inputs (`ConversationContextFormatter.cs:92-139`). Persistent mood replies require typed `{reply,moodDelta}`; a successful unchanged model reply commits delta and transcript together, while invalid/replaced replies do not (`PeopleOfTheIliacBayMod.Dialogue.cs:396-409, 421-460`). TTS captures mood after that commit.
- **Affinity/disposition:** current native disposition is projected for reply/willingness; event appraisal separately captures affinity and revision. The reply prompt explicitly separates liking/disposition from reliability trust (`LocalDialogue.cs:122-147, 164-169`). Do not collapse the friendship/affinity ledger into trust.
- **Trust, fear, resentment:** conversation and willingness projections show unknown trust as unknown and keep fear/resentment separate (`ConversationContextFormatter.cs:260-280`). Appraisal prompt does the same (`NpcExperienceAppraisal.cs:352-360`). TTS protocol carries disposition/trust-known flags, fear, resentment, mood, encounter count, and validated traits (`BreezeTtsTrialProtocol.cs:43-156, 195-231`).
- **Obligations, knowledge, agency:** conversation snapshot binds current commitments, read-source handles, personal state, and motivation projection at one game time (`PeopleOfTheIliacBayMod.ContextSnapshot.cs:172-240`). Reply projection includes current commitments plus bounded needs, goals, priorities, capabilities, resources, threats, and duties (`ConversationContextFormatter.cs:197-241`; `NpcMotivationContextFormatter.cs:22-56`). Source-backed knowledge lookup is a separate stage before ordinary social reply (`PeopleOfTheIliacBayMod.Dialogue.cs:313-323`); it must remain distinct from historical attributed claims. TTS intentionally receives delivery-state fields, not private knowledge or obligations.
- **Exact prompt/time boundary:** D3 route and willingness requests carry current text as `OriginalTurn` separately from bounded attributed history (`LocalDecisionRouting.cs:41-73`; `LocalDecisionWillingness.cs:294-328`). Qwen reply prompt places earlier turns in separate ChatML messages and the latest request in the final user message (`LocalDialogueCompletion.cs:96-139`). Conversation snapshots capture `WorldTime.Now` once at submission (`PeopleOfTheIliacBayMod.ContextSnapshot.cs:145-180`); event appraisal captures current game time separately and rejects evidence newer than that capture (`NpcExperienceCommit.cs:66-75`; `NpcExperienceAppraisal.cs:191-234`).
- **Cancellation ownership:** scene, save epoch, speaker/session, and newer stages invalidate conversation callbacks (`PeopleOfTheIliacBayMod.ContextSnapshot.cs:59-143, 322-370`). D3 requests use their own `LocalDecisionSession` and cancellation handles (`PeopleOfTheIliacBayMod.Decisions.cs:92-133, 173-178`; `LocalDecisionSession.cs:202-216`). Qwen HTTP requests register abort ownership by dispatch version (`LocalDialogueClient.cs:196-229, 285-305`); background appraisal is canceled or retried when foreground work preempts it (`PeopleOfTheIliacBayMod.Experiences.cs:44-58, 130-197, 222-240`). Current source shows no cross-person callback write path in these reviewed flows.
