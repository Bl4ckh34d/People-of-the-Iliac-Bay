# Experience inbox retention implementation plan

> **For agentic workers:** Use the repository's executing-plans workflow to implement this plan task by task. Check off each item only after its stated red/green evidence exists.

**Goal:** Bound saved NPC experience detail without replaying a native outcome, losing pending appraisal, or silently erasing a recorded mood cause or archived speech cue.

**Architecture:** First classify each producer against a durable source. Then add explicit projection and query-availability contracts. Only then retire settled inbox detail in bounded batches. A finite list of old deduplication keys is not replay authority. Source revisions, consumed source markers, and absence of retired source work must remain authoritative after inbox detail is removed.

## Revalidated source status after schema 52

All five production producer classes now have classified admission and durable source state: health episode projection, poison assignment sequences, exact item-transfer receipts, appointment resolution markers, and observed-speech ordinals with accepted-pending state. Public generic enqueue paths reject new events. Do not restart those completed prerequisites from the historical unchecked sequence below.

The inbox itself remains v4 and unbounded: its revision still equals retained entry count, and enqueue copies growing retained detail. Remaining implementation is the coherent inbox-v5/query/retirement change described in sections 2–5: independent monotone ordinals, conservative migration, exact pending speech-context pins, active mood-cause protection, explicit historical availability, archive-addressed speech-cue preservation, bounded maintenance and source-owned retry under real capacity pressure. The archive is not to be deleted or summarized. An inbox cap alone will not bound the separate relationship outcome history or conversation archive.

**Tech stack:** C# Core, DFU/Unity runtime, FullSerializer saves, focused .NET regression projects, owned-fixture native probes.

**Spec:** `docs/2026-10-23-operational-history-design.md` and current Core source; this plan extends that design to `WorldState.NpcExperienceInbox`.

## 1. Classify and close experience admission before pruning

Source-only prerequisite completed after the schema-48 package: `FlushNpcAppointmentExperiences(now, maximumExamined)` retries a resolved appointment's missing experience without rerunning its disposition change, journal write or conversation claim. It preserves the original `ResolvedAt`, including no-shows retried a day later and after save/restore. The runtime calls it with four examined appointments every two seconds, under the existing readiness/pause/conversation gate. Round-robin scheduling and a runtime cache tied to the current appointment list avoid repeatedly copying the full append-only inbox for already projected rows; the 10,000-appointment cap bounds that cache. This is not durable replay protection after inbox retirement, and it does not close the generic admission APIs.

## 2. Decide exact query semantics before retiring detail

### Classified-source migration decisions

Schema50 poison implementation is reviewed, installed and natively accepted; see `docs/2026-10-23-schema50-acceptance.md` for final evidence. The previous API demonstrably reused sequence1 after the sole poison detail was removed from a valid detached snapshot and restored (`work/life-core-20261023/temp/poison-source-red.log`, 0/1). A per-person durable source state now retains last-issued/projected sequences, one exact pending onset and a typed aggregate history-gap record. Each active native assignment receives a one-use epoch/person/adapter/bundle-bound ticket; removing and genuinely reassigning the same bundle begins a new assignment. Existing effects at rebind are baseline only. A queue rejection retains the exact pending source; pressure beyond that finite slot records omitted count/time bounds rather than fabricating an experience, culprit or mood effect. This does not guarantee capture across a process crash between external engine assignment and Core recording. Inbox retirement remains disabled.

Review evidence: the migrated Core main suite reports 1695/1695 passing (`work/life-core-20261023/temp/poison-main-migration.log`). Parent RuntimeCompile completed with zero warnings/errors (`work/life-core-20261023/temp/schema50-runtime-review.log`). `TownTest.ps1` now requires the new `PEOPLE_OF_THE_ILIAC_BAY_NATIVE_POISON_PROJECTION_MARKERS_PASS` marker in addition to the existing poison pass and baseline-restored markers; PowerShell parsing passed. Final schema50 execution and installation subsequently passed: focused11/11, Core1695/1695, runtime zero warnings/errors, native three assignments and unchanged13-file baseline. Exact `UnprojectedDegradedCount` now prevents historical omissions from masking a newly lost Pending. Speech replay RED is also confirmed against the canonical regression project: after valid detail pruning and Restore, the same accepted speech receipt is wrongly admitted again (`work/life-core-20261023/temp/speech-source-admission-red.log`, expected exit 1). Speech admission still needs implementation.

Do not impose a poison-only 10,000-entry cutoff: unrelated existing speech detail must not suddenly suppress valid poison observations. Until a measured shared inbox limit is implemented, v4 has no ordinary finite-capacity rejection. Pending/degraded tests must accurately identify injected invalid/unavailable inbox state or revision exhaustion; they do not prove normal capacity behavior.

Schema50 review constraint: validate that unprojected issued sequences are accounted for by the exact pending event or the cumulative degraded count. A historical omission must not prevent a later exact event from occupying a now-free pending slot. In particular, projected1/pending2/omitted3..4 followed by draining2 must permit pending5 if its projection subsequently fails. Requiring pending to equal projected+1, or degrading5 solely to simplify a contiguous-tail representation, would lose an event that the bounded pending slot can preserve. Cumulative gap accounting is a lower-bound validation aid, not proof of exact historical gap locations. Final focused tests must cover this transition before package acceptance.

### Speech source admission for the next schema

The canonical `tests/NpcSpeechSourceAdmission.Regression` replay RED is confirmed: after valid detail pruning and Restore, the same accepted speech receipt enters again (`work/life-core-20261023/temp/speech-source-admission-red.log`). The current `SubmitFreeText` constructs the receipt from `CaptureNpcExperienceInboxRevision()+1`. Its `CaptureConversationCommandTurn` wrapper ignores failed command capture; context capture can also fail before command capture while still appending a visible unavailable reply. A stable speaker therefore does not always obtain a command-issued ordinal. `QueueObservedSpeechAfterAppend` currently enqueues other appended turns and clears the runtime receipt even on failure. The atomic mood path writes speech with journal and mood; action replies can restore a captured receipt before fallback append. Evaluation callers and `NpcFrameworkPersistenceProbe` also use the public speech API. Migration must cover every producer, not only the generic enqueue method.

For schema 51, persist a bounded per-person observed-speech source state, separate from `NpcConversationCommandSession`: monotonic `LastIssuedOrdinal`, `LastAcceptedOrdinal`, `LastProjectedOrdinal`, and at most one exact accepted-pending projection. Validate `0 <= projected <= accepted <= issued`, unique Core-known person ownership, bounded exact text/time, session and branch provenance, applied-effects mask, native immediate-affinity delta and family-threat disposition, and a pending/ordinal relationship that permits gaps from issued requests which never produced a reply. Do not infer issued or accepted authority from old inbox IDs. Schema 50 and older load with zero speech cursors and unchanged legacy inbox detail; reject nonempty future speech fields in an older save envelope. A current-schema save with duplicate owners, invalid monotonic cursors, or a pending source inconsistent with its cursor fails detached validation. Use a new scope/person/speech-ordinal receipt-ID domain, preserving old receipts as historical detail without making them new-source authority.

Issue a one-use `NpcObservedSpeechTicket` at the start of `SubmitFreeText`, before fallible `CaptureConversationContext`, for a managed, Core-known stable speaker in the current Talk session. Bind it to store/epoch/branch, person, session, exact submitted text, observed time, and its own issued ordinal; bind the resulting request/context snapshot when capture succeeds. A command turn may still be captured for action admission, but speech issuance must not require that turn. If issuance fails for a known managed speaker, fail closed before routing or accepted presentation and do not attribute an observed-speech event. An unmanaged or Core-unknown speaker may continue the ordinary UI dialogue explicitly without a persisted observed-speech event; it must not create a caller-stamped substitute. Busy submissions do not issue speech. Same-request command acceptance may close the command turn without invalidating this speech ticket. A newer speech request, Talk/session close, scene/save epoch change or Restore invalidates an unaccepted ticket. After acceptance, only the exact saved accepted-pending source can retry across Restore; a live callback cannot recreate it.

Core APIs should separate `TryIssueNpcObservedSpeech(...)`, optional `TryBindNpcObservedSpeechContext(ticket, binding)`, exact-source acceptance, and `TryProjectPendingNpcObservedSpeech(...)`. Acceptance checks the live ticket, session/request/text/time/branch, actual native affinity and family-threat facts, and the exact effects mask. For ordinary replies, publish inbox plus accepted/projected cursors in one validated candidate when enqueue succeeds. If enqueue fails after a reply was appended, retain exactly one accepted-pending source with the original text, time, mask and native effects; retry only from that source and block or explicitly fail further accepted speech while the finite pending slot is occupied. A bare retained dedup key cannot reconcile the pending source; require the matching source-derived historical row. On a rejected admission, do not advance accepted/projected cursors or clear a retryable source. Public caller-constructed `TryEnqueueNpcObservedSpeech` overloads become negative compatibility gates; legacy saved pending rows still appraise.

`TryCommitAcceptedMoodExchange` and accepted action wording must stage the speech source cursor with their existing journal, mood and inbox candidate, then publish once before presentation. Preserve immediate-affinity and family-threat provenance, exact text and applied-effects mask. Deferred TTS presentation of an already accepted exchange must not enqueue a second source. Native topic/map/clock/home replies, hostility or refusal, unavailable fallbacks, action/task acknowledgements, and social/model fallback paths all reach `AppendRememberedDialoguePair` or `AppendUnrecordedDialoguePair`; pass the exact captured ticket through these paths and `QueueObservedSpeechAfterAppend`, rather than rereading and clearing a mutable global receipt. `ActionReplies` and `ActionWording` must retain that same ticket across their asynchronous or fallback branches. A context-capture failure can still accept the pre-issued ticket only if its fallback line was actually appended and its source checks pass.

Regression order: first replace the canonical synthetic positive RED setup with classified accepted speech, then prune only its detail and prove that old ticket/ordinal replay and both public generic overloads fail after Restore. Cover a stable speaker with failed command/context capture, unmanaged UI without a persisted event, known-speaker issuance failure before routing, wrong text/session/request/branch/epoch/mask/affinity/family-threat facts, same-request command closure, and newer request/session close/Restore invalidation. Prove mood/social/action atomic publication, deferred presentation without duplicate admission, ordinary reply queue failure followed by saved pending retry exactly once, and later higher-ordinal success. Test schema-50 migration with all legacy rows retained and zero new authority, malformed current/legacy source fields, and FullSerializer native topic/refusal/action/social paths. The existing v4 inbox has no ordinary finite cap; use an explicitly injected queue rejection or revision exhaustion for pending tests, not a claimed normal capacity case.

The UI transcript and Core save cannot form one crash-atomic transaction. A process crash after an ordinary UI append but before Core acceptance can leave a displayed reply without a saved accepted source; a mood transaction can save acceptance before deferred display. The accepted-pending source closes retry gaps after Core acceptance, not this external UI/Core crash window. The trusted synchronous native adapter remains the boundary; source tickets prevent stale, cross-store and replayed callbacks, not hostile trusted in-process fabrication.

- Appointment projection uses a persisted source-row marker: None, Pending, Projected, or LegacyUnavailable. Projected is the authority when retained inbox detail eventually disappears; it must not depend on a second unbounded tombstone ledger. Exact retained source evidence may reconcile a Pending marker. Matching only a deduplication key is insufficient.

## 4. Retire in bounded batches with explicit pressure

- [ ] Implement `MaintainNpcExperienceInboxHistory(now, maximumExamined, maximumGroups, underCapacityPressure)` or equivalent. A call scans a bounded number of rows/groups, advances a persisted or validated rotating cursor, prepares a detached state, validates it, then publishes once on the main thread. It does not run on load, pause, or an unready game state. Use game time for semantic eligibility and real time only for per-frame scheduling.
- [ ] Pin every pending row; required speech predecessors; native rows with a remaining supported-time mood cause; and attributed speech whose exact archive cue has not been projected. A deferred row may retire only after its remaining context/query obligations are discharged. Mark source projection before or atomically with retirement. Never infer successful appraisal from native event acceptance.
- [ ] Define a hard retained-detail cap and a separate small normal maintenance budget. At cap, a bounded complete pressure sweep may evict only eligible settled rows. If all rows are pinned, reject or defer new admission with a distinct capacity reason and no partial source consumption. Native producers whose effects have already happened need a durable source-owned retry/pending-projection disposition; otherwise they must not advance their projected marker. Do not keep an unbounded dedup tombstone list.
- [ ] Measure worst-case all-pinned scan, ordinary maintenance latency, saved bytes and enqueue cost. This caps the inbox only; conversation archive and relationship history require their own separate bounds. Do not claim total-save boundedness from this work.

## Open decisions to resolve before implementation

### Source-review constraints (after the installed schema-48 checkpoint)

- Use an explicit per-person historical-availability floor for retired mood detail; old unsupported queries must return a typed unavailable result. Preserve current and future supported causes. Since the configured mood half-life may change, retirement must prove zero remaining effect even under the maximum supported future half-life (currently 86,400 seconds), not merely the profile's current value. This is a query contract, not autobiographical summarization.
- Protect exactly the speech context selected for each pending native event. The current selection skips turns that do not fit the remaining 1,800-character budget, so protecting the six immediately preceding rows is insufficient. A selected predecessor may be Pending, Deferred or Consumed. Pending attributed-speech events use their own observed turn. Deferred rows are currently terminal, not automatically retryable.
- Immutable archive cue identity must use ArchiveId, ChunkHash, RecordIndex and PersonId. CheckpointHead changes when the archive grows, even for an old record; validate membership and bind to the current query checkpoint instead of using an old head as the sole lookup key. Exact old cue availability still requires a separate finite-history contract or protected receipt; missing detail must never become a fabricated neutral cue.
- DFU LiveEffectBundle has no stable instance identifier. A poison effect key identifies its type, not its assignment. A per-person sequence is necessary but not sufficient: admission also needs a one-use native assignment capability tied to the current binding epoch, and a durable pending projection before inbox pressure can reject the event. Rebinding must baseline existing effects without reporting them as new assignments. Preserve the native-adapter trust boundary explicitly; arbitrary hostile in-process calls are not authenticated engine events.
- The first appointment fix can remain schema-compatible: the persisted resolved appointment is already the durable native outcome. Retry projection from its original ResolvedAt and status without replaying disposition or journal changes. Before inbox retirement is enabled, replace the current retained-inbox dedup dependency with a durable classified-source projection marker.

1. **Historical mood contract:** choose a typed availability floor or unbounded exact history. A finite hard cap requires the former. Preserve active current/future causes regardless.
2. **Archive cue projection:** specify the exact address-linked bounded projection and whether a source can ever be retired before its archive match exists. If exactness is unprovable, pin it and expose pressure.
3. **Legacy authority:** decide which old rows have a surviving source for safe reconciliation. Do not silently discard unverifiable old history or manufacture a source cursor from a dedup key.
4. **Native queue pressure:** specify source-owned retry semantics for effects already observed; capacity rejection alone is insufficient for health, poison, transfer and appointments.
5. **Limits and timing:** select measured retained-detail cap, batch budget and supported historical window after the red/green benchmark. Do not choose an arbitrary count that would erase a valid mood cause.
