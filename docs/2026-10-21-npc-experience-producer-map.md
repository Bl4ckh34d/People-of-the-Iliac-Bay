## Current boundaries

Core types `NpcExperienceEvent` and `NpcDirectedRelationship` remain policy types. Runtime producer search finds no call to `NpcExperienceEvent.FromNativeOutcome`, `FromAttributedSpeech`, or `NpcDirectedRelationship.TryApply`. No shared event ledger or appraisal adapter consumes the receipts yet. Native source evidence must be converted only after a verified outcome and recipient-knowledge check.

Do not expose hidden incident culprit or player-attribution fields to an NPC merely because the internal alarm system stores them. Prompt context must use observer-specific evidence: direct sight, permitted report, or an explicitly recorded conversation. Unknown cause stays unknown. A model claim never upgrades a native fact.

## Suggested first integration

Use appointment outcomes because they already have stable IDs, persisted game-time evidence, and one-shot resolution. Emit at most one event per appointment ID and observer/target direction. Start with `attended` and confirmed `player-absent`; keep `npc-absent`, interrupted, and unknown cause out of NPC blame. Gate `player-absent` on the existing `OutcomeRecorded`, `NpcWaitedSeconds`, and `NpcLastSeenAt` fields; do not add a second wait loop or relax continuity thresholds.

For confirmed player absence, let the new appraisal update directed relationship dimensions through a separate event receipt. Do not run the old disposition penalty a second time: `ResolveAppointment` already calls `ApplyAppointmentDispositionPenalty` when `NoShowPenalty > 0`. Keep its existing memory/penalty behavior intact. Deduplicate by appointment ID at the eventual ledger commit, not only by an adapter-generated receipt string.

After that path has replay, save/load, stale-revision, and observer-knowledge tests, add player-to-NPC item handovers as a transfer-only event. Label transfer facts accurately; do not call transfer a gift without verified intent or contract evidence. Treat damage attribution, healing/status onset, and gold gifts as later work requiring native outcome callbacks and explicit observer evidence.

## Required tests before expanding producers

- Replaying same appointment ID across callbacks, reload, and adapter retries changes relationship at most once.
- `attended` and `player-absent` map to correct directed observer/actor pairs; `npc-absent`, interrupted, and missing evidence cannot assign NPC blame.
- Legacy no-show penalty and memory remain exactly once; event appraisal does not call legacy penalty path again.
- Long polling gaps cannot qualify as continuous wait; paused game time does not accumulate wait.
- Delayed appraisal loses on relationship/event revision conflict and cannot partially write.
- Item transfer requires committed source/target receipt and exact UID/count; offer-only, rejected action, rollback, service payment, and shop purchase do not become gifts.
- Health samples, poison persistence, death-only incident, or secret internal culprit data never become an injury/poison event or NPC knowledge without a dedicated source hook.
