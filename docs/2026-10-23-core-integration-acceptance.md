# Core integration acceptance requirements

This checklist defines evidence required by the active implementation goal. It does not mark the common planner complete.

## Arbitration and ownership

- Native quest ownership, death, travel and active danger retain their authoritative restrictions. Selection cannot grant a second movement owner.
- Health, safety and duties compete through a shared selection contract. Stored priorities must affect selection; a decorative unused selector is insufficient.
- Candidates require current executable capabilities, resources and targets. Unknown availability cannot count as feasible.
- Stable ties and retaining feasible current work prevent oscillation. Save/reload must not reroll the selected intent.
- A failed or unavailable selected plan cannot silently fulfill a need or create stock, money, access or treatment effects.

## Goal/task identity

- A task records its originating goal and admission provenance. Subsequent native evidence updates must not erase that historical relationship.
- Reused goal IDs, particularly `goal:native-recovery`, must distinguish successive injury episodes. Tests must cover a completed prior episode followed by a new injury.
- Admission, successful action, task completion and fulfilled need are separate facts. Native state determines fulfillment.
- Cancellation, failure, changed need and completed effects reconcile through the common lifecycle without discarding physical return or paid effects.
- Legacy tasks without goal provenance retain their valid existing behavior; migration must not invent an originating goal.

## Operational history

- Replace lifetime ceilings through explicit versioned retention, not larger arbitrary limits.
- Preserve active tasks, physical returns, pending commitments and all references needed to validate their effects.
- Replayed old proposals remain suppressed after retention and reload. Save branches and multi-year progression require explicit tests.
- Autobiographical memory compaction remains excluded.

## Delivery evidence

Require reviewed production call sites, meaningful Core regression cases, old-save roundtrips, clean runtime compilation, and native acceptance of the integrated paths. Build only after participating implementation agents finish. Existing schema-45 healthcare evidence remains a baseline, not proof of this new integration.
