## Existing authority and remaining dependency

Production admission is already classified. Health uses the actor's projected-through vitals revision and pending health episode; poison uses per-person assignment sequence plus pending/degraded disposition; transfers use the completed action's exact projection marker; appointments use the resolved row's projection state; observed speech uses accepted/projected ordinals and one saved pending source. Public caller-built native and speech enqueue overloads fail closed. Retained `HasOutcome` may reconcile a matching *pending* source while detail exists, but it is not replay authority after retirement. Keep source checks and their native retry paths; do not reimplement them.

The v4 inbox still requires `Revision == Entries.Count`. Its dedup search, admission copy, mood-cause query, six-turn appraisal context, and archive emotion-cue matching all read retained rows. `NpcRelationshipLedger.AcceptedOutcomes` is a separate unbounded ledger and does not replace inbox admission or this project's scope.

## Version and migration contract

Add `NpcExperienceInbox` v5 fields `Revision` (monotone accepted enqueue ordinal), `RetiredCount`, and ordered retained entries with `EnqueueOrdinal`. On enqueue set `EnqueueOrdinal = Revision + 1`, then increment `Revision`; status changes and retirement never increment it. Validate `0 <= RetiredCount <= Revision`, `Revision == RetiredCount + Entries.Count`, and unique strictly increasing retained ordinals in `[1, Revision]`. Validate observer/key uniqueness among retained rows. Missing ordinals account for retirement, never for a new source authorization. A separate `DetailRevision` increments on any status replacement, cue projection, availability-floor change, or retirement; captured reads pin it. Do not use a truncated hash or row count as source truth.

Migrate v1–v4 through WorldState schema 53 by assigning original array positions `1..Entries.Count` as ordinals, setting `RetiredCount=0`, and preserving every row and status. Legacy schema <35 starts empty. Reject v5 fields in a legacy envelope. Do not derive projected cursors from dedup strings, or mark an unresolved source projected without its exact retained receipt and its independent surviving source. Existing migration normalizations remain detached and input-immutable. Validate source/retained-row consistency on the fully copied WorldState, especially speech receipt ordinal, poison sequence, health projected frontier, appointment state, and transfer marker. A retained legacy row lacking reconcilable source stays pinned; it cannot silently become a replay tombstone.

Use a hard **new-admission** budget of 8,192 retained rows globally and 256 per observer, subject to performance evidence before native deployment. A pre-v5 save may already exceed either budget. Import it losslessly with an explicit legacy-overflow marker tied to its imported `Revision`; block further inbox enqueues while over budget and retire eligible rows. If all imported rows are pinned, save remains oversized until their obligations settle. This is a necessary exception: arbitrary old pending detail cannot be both preserved and instantly hard-capped. Current-version saves cannot mint a new overflow allowance. A source with an already-observed native effect must keep its existing saved pending/retry disposition while capacity is unavailable; never report an invented appraisal or advance projected markers.

## Exact dependencies before removing a row

1. **Appraisal.** Never retire `Pending`. A `Deferred` row is terminal for appraisal but may still be speech context or query evidence. The worker's oldest-pending order and ticket's exact entry/revision checks remain valid. Retirement replaces the inbox object; no in-place list mutation.
2. **Speech context.** Extract the actual `RecentObservedSpeechContext` selector into one shared pure function. For each pending inbox event and each saved source-owned event awaiting projection, pin exactly the earlier observed speech rows it would select: descending `(ObservedGameTime, DeduplicationKey)`, at most six, skipping turns that exceed remaining 1,800 characters. Include `Consumed` and `Deferred` predecessors. If a legacy pending source lacks exact event time/key, pin its observer's speech detail or defer retirement; do not guess. Also retain the selector's current six-turn frontier per observer for the *next* event. Otherwise a future appraisal can lose context even when no event is pending during maintenance. Before retiring that frontier, require a later frontier that makes it unnecessary. Add a durable per-observer `LastAcceptedObservedAt` for observed speech and require new issuance at or after it, before UI append; current speech ordinal alone permits backdated observed times. Any newly observed native source with an older timestamp must already be represented among saved pending sources before its predecessors retire. Do not turn missing predecessors into empty context.
3. **Mood.** Keep every consumed native row with nonzero `AppliedMoodDelta` while `MoodRecovery.ValueAt` can be nonzero at or after maintenance time under the maximum supported half-life (currently 86,400 game seconds). Test all affected rows, not only the current top three. On retirement set a monotone per-person supported-from time to at least the maintenance time. Add a typed mood-cause read result: `Available(text)` or `UnavailableHistoricalDetail(supportedFromAt)`. The existing string API must fail closed for a query before that floor, never return `string.Empty` as if no cause existed. Current/future supported-time text stays byte-identical. A change to the supported half-life ceiling requires migration/review before allowing larger values.
4. **Archived speech cue.** `CaptureConversationMemoryCompactionContext` currently derives emotion cues from consumed attributed-speech inbox rows. Keep a row until it has one exact archived source address and its exact appraisal/receipt payload has been committed to an immutable, content-addressed cue sidecar. Do not rewrite historical conversation chunks. Sidecar address identity is `(ArchiveId, ChunkHash, RecordIndex, PersonId)`; `CheckpointHead` is a changing membership proof, not source identity. Validate that the source chunk belongs to the *current* archive checkpoint when reading or writing the cue. Bind receipt, episode, utterance, speaker, text/time and applied appraisal; preserve ambiguous-match rejection. Context capture merges retained receipts and sidecar cues, accepts exactly one matching cue per candidate, and never emits a neutral cue when detail is unavailable. Sidecar is exact archive provenance, not new speech or a memory summary. Its append and inbox retirement publish one validated checkpoint: write immutable cue bytes first, then publish the WorldState cue head and row removal; an orphan file after failed publication is harmless. If archive match, sidecar write, or validation fails, pin the row and expose capacity pressure. The separate archive/sidecar can grow; this task bounds only operational inbox detail.
5. **Source.** Source ownership must already prove projected status before a settled row retires. Recheck the five classified producers. Change any `HasOutcome`-only retry path so its projected marker wins after detail removal; use exact retained detail only to reconcile a still-pending marker. Never regenerate a consumed native outcome solely because its key disappeared.

## Bounded maintenance and pressure

Implement `MaintainNpcExperienceInboxHistory(now, maximumExamined, maximumGroups, underCapacityPressure)` returning examined, retired, pinned, deferred, and `ScanComplete`/`AllPinned` only after a full unchanged-ledger sweep. Routine runtime budget: at most 16 examined and four retired groups per two-second tick after source drains and appraisal, when game is ready and unpaused. Keep a rotating cursor across unrelated enqueues/status updates; clamp on shrink. Candidate selection may inspect bounded rows, but report full-world validation and archive lookup cost separately. Prepare detached inbox, source/cue marker and availability floors, validate one full candidate, then publish once. No source effects, archive checkpoint, or read snapshot may observe a half-retired state.

At either cap, use bounded pressure slices over the targeted observer and/or global ledger. Pressure can remove settled recent detail that passes every pin; ordinary maintenance may retain the newest 32 settled rows per observer or seven game days for short-term inspection. Do not let that preference block capacity. If one slice finds nothing, return `DeferredScan`, not `AllPinned`; keep the native source pending and retry after later slices. Admission returns a distinct `CapacityDeferred` when no room was made. No unbounded key tombstones. A truly all-pinned ledger cannot accept more exact detail without violating the bound; do not drop pending appraisals to manufacture room.

`NpcMemoryReadSnapshot` must pin inbox detail revision and cue archive head in addition to its current state/inbox reference checks. Any retirement or cue projection invalidates a captured mood/cue read before final publication. A typed historical-unavailable response must survive SnapshotForSave/Restore and branch reads.
