## Fixture sequence in `NpcExperienceInboxV5NativeProbe.cs`

Restore the snapshot into a *detached* store. This is the same proven native source boundary used by `NpcExperienceProjectionNativeProbe.VerifyNativeHealth`; do not create a new injury or directly enqueue an event.

2. **Create one genuine, controlled appointment source in that detached store.** Choose a fixture settlement/building absent from the source snapshot, materialize one resident with `GetOrCreate`, and assert its identity is distinct from the healed resident. Set `appointmentAt = HealthEpisodeLastChangedAt - 8 * 86400` only if the resulting time is valid and positive; otherwise fail with a fixture-time diagnostic. Use an ID scoped to the detached fixture. Build the accepted `AppointmentRecord` with real venue, `StartsAt=appointmentAt`, `EndsAt=appointmentAt+60`, zero grace and 600 patience. Call `TryReserveAppointment(record, appointmentAt-500, out reason)`, then `ObserveAppointment(id, appointmentAt, true, true, false)`. Require a saved `attended`/`OutcomeRecorded` record with `ExperienceProjection == Projected` and an exact `NpcAppointmentExperience.TryCreate` event in the Inbox. This is a controlled Core source, not a fabricated inbox row or an actual native meeting.

3. **Consume that row without a model.** Initialize that controlled resident's personality/baseline as `NpcExperienceCommitProbe` does: `GetOrCreateNpcPersonality`, `SetConversationBaseline`, and `RecordConversationEncounter`. Capture `TryCaptureNpcExperienceAppraisal(controlledPersonId, appointmentAt+1, out ticket)`. Verify the chosen delta is legal in a focused Core test before the native run; if not, use another valid deterministic response and retain the same no-LLM guarantee. This old mood effect must have decayed before retirement under the supported maximum 86,400-game-second half-life.

4. **Project the native health source, then preserve it as a pin.** Call `FlushNpcHealthExperiences(HealthEpisodeLastChangedAt+61, 60, 100)` on the detached store. Match the returned source to the actual first/last vitals revisions, healing total and final health. Require `HealthExperienceProjectedThroughVitalsRevision == source.LastVitalsRevision`, no pending health *episode*, and one exact **Pending inbox appraisal row** for the health outcome. Do not appraise this row. Distinguish the cleared health source episode from its still-pending Inbox appraisal obligation.

5. **Capture pre-retention evidence.** Snapshot the v5 Inbox and save both exact rows' `OutcomeId`, observer, status, `EnqueueOrdinal`, `Revision`, `RetiredCount`, `DetailRevision`, and the actual health source cursor. Require the controlled row consumed and the native health row pending. Take one pre-retirement FullSerializer round trip via `SaveLoadManager.Serialize(typeof(WorldState), ...)`, temp JSON file, `SaveLoadManager.Deserialize(..., true)`, and `WorldStateStore.Restore`. Require v5 counters, both statuses, source markers, and row ordinals survive. At large DFU game times, compare live timestamps to decoded wire timestamps within 0.001 game second and thereafter compare restored values to the decoded wire exactly; no broad tolerance for absent IDs, receipts, revisions, or state. **On this restored store**, capture a mood-cause `NpcMemoryReadSnapshot` for the controlled resident with `TryCaptureNpcMoodCauseRead(controlledPersonId, maintenanceAt, 600, out read)`; require it current immediately before maintenance. This makes subsequent invalidation attributable to retirement, not to Restore's owner/epoch change.
