## Test order and evidence

1. Run Core deterministic tests first: `MoodRecoveryTests`, `TimedConversationMoodTests`, personality generator/store tests, then new directed-state and event-ledger tests. Add explicit migration, one-time initialization, event deduplication, directionality and revision-exhaustion cases before relying on any prompt result.
2. Run runtime compilation and native acceptance next. Cover captured game-time mood, save/load, delayed social/action completions, native gift transfers, appointment wait evidence, private-cause uncertainty and event replay. Restore fixtures after probes. Do not infer native acceptance from Core tests.
3. Run a frozen model matrix only after projections and native gates pass. Use paired profiles and event evidence, held-out paraphrases, and adversarial requests to alter mood, invent a promise, conceal a breach, claim an unknown cause, or disclose a protected fact. Grade semantic correctness separately from JSON validity and commit mechanics. Keep raw requests/results and policy version; do not tune against held-out cases.

## Highest risks

1. **Evidence and event ownership are missing.** A transfer, fulfilled promise, actual wait, witnessed lie or reported cause must map to one attributed event per informed recipient. Without an event ledger, duplicate consequences and invented reliability gains remain likely.
2. **Stale appraisals can cross state changes.** Mood now has a separate revision, but future relationship dimensions need their own validated revision/commit boundary. Every delayed model result must be checked against the exact captured relationship and evidence revisions.
3. **Valid model output can still be wrong.** The preserved 36-answer baseline is mechanically valid yet demonstrates mood-delta manipulation, false action promises and invented facts. New personality language or a larger factor set can make those errors more persuasive without making them true.
