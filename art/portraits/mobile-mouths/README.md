# Mobile portrait mouth study: records 77 and 78

Status: the user visually approved full-frame version 5 for records 77 and 78 ("Sieht super aus so, können wir lassen") and accepted minor differences from the original likeness. The current browser preview uses those sheets. Runtime integration remains open; they are not installed in the game. Earlier mouth-cutout versions remain historical rejected/experimental drafts.

## Current approach: full-frame version 5

The edit target is the exact 3×3 sheet of repeated, nearest-neighbor enlarged original portraits (`tfac-077-reference-grid.png` and `tfac-078-reference-grid.png`). The built-in `image_gen` tool edits the full sheet with the face context present. Prompts request restrained A–H/X speech shapes, original lip corner positions, no exaggerated opening, consistent face proportions, palette, hair, eyes and framing, and no gutters or labels. The complete generated cells are displayed directly; no mouth is cut out, rescaled separately, color-segmented or pasted back. Minor source-to-generated differences are explicitly allowed by the user. Stability between generated poses still matters.

`tfac-077-full-frame-v5.png` and `tfac-078-full-frame-v5.png` are 1254×1254 sheets with 418×418 cells in `A B C / D E F / G H X` order. The browser samples full cells into the native 64×64 display canvas with nearest-neighbor rendering. Both closed poses come from the generated full-frame set, which avoids switching between original and generated appearances at every pause. The original is shown separately for comparison. The existing WAV and Rhubarb timeline drive the same sample-based viseme selection. No new voice audio was synthesized for this comparison.

This supersedes the earlier strict unchanged-pixels-outside-mouth art requirement for these new mobile portraits. It does not relax person/session/audio ownership, stale-callback or per-face asset checks required for runtime integration. The existing Gwen runtime remains unchanged.

## Historical cutout experiments

The preceding version 4 used original TFAC00I0.RCI records 77 and 78 as immutable identity bases. The built-in `image_gen` tool received only the native mouth rectangle `(18,35,28,20)`, enlarged 16 times with nearest-neighbor copying. It generated a 3×3 mouth-only sheet ordered `A B C / D E F / G H X`. The prompt asked for M/B/P closure, narrow consonant opening, EH/AE, AH, OH, OO/W, F/V, raised-tongue L, and original neutral mouth, preserving palette, alignment and pixel style. The tool has no explicit mask argument; generation received only the mouth crop, and composition enforced locality afterward. The user still found the animation unnatural and proposed full portraits instead.

The old `tools/BuildMobilePortraitMouthAssets.ps1` writes a rectangular skin patch and remains only for reproducing rejected versions. An independent pixel audit found 197/198 or 198/198 changed pixels in version-3 B, including all perimeter pixels. Native lip bounds are `(24,42,16,5)` in both faces. `tools/ComposeMobileMouthContours.ps1` now selects the red-lip contour, fills between lip edges to retain teeth/tongue/cavity, and scales that contour to the native lip anchors. It does not copy generated surrounding skin. Original lip pixels uncovered by a new shape are filled from native adjacent skin at the same row. This avoids leaving the old closed mouth under a narrower new mouth. A/X remain exact originals. This red-lip heuristic is restricted to records 77/78; it is not a general solution for beards, unusual palettes or other portraits.

Files `tfac-077-visemes-v4.png` and `tfac-078-visemes-v4.png` are 192×192 sheets with nine 64×64 cells. Manifests record contour geometry and output hashes. `pixel-verification-v4.json` independently reopens saved PNGs: zero changes outside native envelope `(24,42,16,8)`, exact original A/X; 57–103 pixels change in the other poses. These are technical invariants, not visual acceptance. The speech poses approximate viseme groups, not anatomically exact phonemes.

`preview.html` compares each original against the composed animation, driven by the existing female voice reference WAV and a newly generated Rhubarb sample timeline. The sample voice is shared for visual comparison; this does not assign the same voice to both NPCs. Audio hash matches the timeline provenance; estimated cues contain A–G and X. H can be inspected manually. The preview is published under the already-running loopback gallery at `http://127.0.0.1:8096/mobile-mouths/preview.html`.

The runtime remains the previous Gwen/face-76 prototype. Integrating additional portraits requires an explicit per-face atlas registry, native/replacement texture compatibility checks and preserved person/session/audio binding. Do not broaden the Gwen allowlist or reuse its face-specific atlas for these records. The mobile portrait selection table covers native records 0–359; this study covers only 77 and 78.
