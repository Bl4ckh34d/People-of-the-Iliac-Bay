# Qwen, D3, DFU and Breeze switch procedure

This procedure runs only after framework acceptance and while the intended D3, Qwen and DFU trial are active. It does not stop or launch processes automatically. `model_cycle.py` validates an operator-captured JSON record; it never reads process tables or changes services.

## Native pilot with CPU-resident Qwen and warm Breeze server

For normal native listening, keep Qwen on CPU and Breeze on its dedicated GPU server. `RunNativePilotAudio.ps1` reads `executionDevice` from `local-llm/active-model.json`; absent value means `CPU`. It verifies Qwen's live flags and exact process identity, leaves that process running, and rechecks identity and mode while Breeze synthesizes. Do not use the stop/restore measurements below for CPU mode.

Start or keep the warm Breeze server on loopback port 8094, then run:

```powershell
pwsh -NoProfile -File tools\BreezeTtsTrial\RunNativePilotAudio.ps1 `
  -TrialRoot work\breeze-tts-20261021\native-pilot-03 `
  -OwnedGameProcessId <DFU_PID> `
  -TtsServerEndpoint http://127.0.0.1:8094
```

The runner requires matching warm `audio.cpp` SSE evidence, server endpoint, synthesis and first-audio timings, and at least one audio delta. It rejects CLI evidence on this path. GPU Qwen stop/restore remains a legacy measurement path only when `executionDevice` explicitly says `GPU` and live command flags prove the same mode.

## Before switch

1. Wait for the current native mood probe and every Qwen dispatch to finish. Do not stop Qwen while a request is active.
2. Finalize the exact text for the next TTS sample. Record its monotonic `textFinalized` time. Confirm dispatch idle, then record `dispatchIdle`.
3. Read Qwen selection from `local-llm/active-model.json`. Resolve the selected model path exactly as `ResolveLocalDialogueModel` does. Record the file SHA-256, or `absent` if launcher fallback applies. Do not edit this file during trial.
4. Independently inspect Qwen PID, process creation time, executable, full arguments and port-8080 listener owner. Require one listener on `127.0.0.1`, exact `llama-server.exe`, active model path, `-c 4096`, `--host 127.0.0.1`, `--port 8080`, and `-np 1`. Check `/health` and `/props`: healthy, same exact model path, context 4096 and one slot.
5. Record exact D3 PID, executable and creation time. Record exact DFU game PID, executable and creation time. Confirm both still run. Never stop either process.
6. If any PID, executable, creation time, listener owner, model path, context, slot count or active configuration is uncertain, stop procedure. Never stop a listener or process that does not match the independently verified Qwen identity.

## Switch and restore

1. Record baseline GPU free/used memory and monotonic time. Stop only the verified Qwen PID after steps 1–5 pass. Record its exact PID and creation time.
2. Wait until Qwen listener is gone and GPU free memory stabilizes. Record observation time and GPU memory. If another process owns port 8080, do not touch it.
3. Run one short cold Breeze request with the pinned `audiocpp_cli.exe`, Breeze GGUF, model spec, and `coordinator.py`. Record exact executable/model paths, hashes, process PID/creation time, monotonic process start/ready, model-load start/ready, synthesis completion, release, GPU samples, audio-ready and first-audible times.
4. Run a second short request in a new CLI process with the same model and configuration. Label this `warm-file-cache-new-process`. This measures warm OS file cache with a fresh process and a fresh model load. It does not mean Breeze weights stayed resident in RAM or VRAM.
5. Wait for both synthesis processes to exit and GPU use to settle. Do not restart Qwen while Breeze is synthesizing. Once a complete WAV is buffered and playback begins, Qwen reload may overlap playback; record whether Qwen becomes ready before playback ends.
6. Restart Qwen through existing `tools/StartLocalDialogue.ps1`, using same selected active config, port 8080 and context 4096. Do not write a new active model selection. Verify `/health`, `/props`, exact model path, one slot and exact new listener PID.
7. Verify D3 and DFU retain original PID and creation time. Confirm no process outside the exact Qwen and recorded trial audio.cpp children stopped. Confirm active-model config hash matches baseline. Record all events with one monotonic clock and all GPU samples with timestamps.

If any step fails, do not kill an unknown PID or repair the service by guesswork. Preserve logs and the partially completed record. Restart only the exact original Qwen selection through its existing launcher after the TTS child has exited, then verify D3 and DFU remain untouched.

## Validate observations

Capture a JSON record matching `model_cycle.py` input. The validator requires Qwen before/after listener snapshots, D3/DFU identities, the active-model config hash before/after, two distinct TTS process identities, monotonic timings, GPU-free-memory samples and load-duration measurements. It rejects changed Qwen configuration, changed D3/DFU process identity, unknown stopped PIDs, active dispatch, non-loopback Qwen listeners, and unsupported RAM-residency claims.

```powershell
python tools/BreezeTtsTrial/model_cycle.py path\to\captured-cycle.json
python -m unittest tools.BreezeTtsTrial.test_model_cycle -v
```

The helper trusts supplied snapshots. It cannot prove those snapshots came from Windows, validate an operator's process-selection judgment, or restore anything. Perform independent read-only process/listener checks before the stop step.
