# Frozen NPC factor contrasts

`paired-scenarios-v1.json` freezes the original 29 matched pairs (58 arms). `paired-scenarios-v2.json` preserves those pairs and appends six targeted contrasts (35 pairs / 70 arms total). Every arm uses the existing NPC Architecture fixture vocabulary (`input.npc`, `world`, `history`, `playerText`, `availableTools`, `options`) and the existing choice-set idea (`expected.allowedChoices` is represented here as `acceptableD3Choices`). Pair metadata adds one-factor contrast, native eligibility, and Qwen voice review. This is a preparation bundle, not a runnable harness suite yet. Every v2 addition is marked `planned_adapter_only`: its options and event semantics are review contracts, not current native-runtime support claims. Core event handling remains partly planned; do not infer a complete implementation from fixture coverage.

The native anchor is the existing MoodEvaluation person ID and save name. Only identity and setting come from that probe fixture. Event times, traits, relationships, witnesses, status, needs, contracts, outcomes, and options are explicitly synthetic. The corpus claims no gameplay support or model accuracy.

## Review rubric

Review native validity and model semantics as separate outcomes.

1. **Native eligibility:** Compare the selected option ID with `expectedNativeEligibleOptionIds`. This set represents the options native validation could authorize in the synthetic case. An option outside it is a validity failure even if its dialogue sounds plausible. Native systems still own capability, money, item ownership, consent, access, schedule, contract terms, outcome receipts, and effects.
2. **D3 choice quality:** Compare selected ID with `acceptableD3Choices`. This set intentionally allows multiple legitimate decisions, including clarification, refusal, or an alternative when supplied facts permit them. Do not score against one gold choice or one exact utterance. A choice can be eligible yet less suitable to the supplied preference evidence; record that as a review judgment, not a native failure.
3. **Qwen voice and claims:** Review whether the reply sounds like the supplied stable personality and current mood, preserves uncertainty, reflects only actor-known evidence, separates affection from trust, and avoids inventing an action or result. `qwenReview.must`, `voice`, and `forbid` are semantic review prompts, not phrase-matching rules. Accept different wording when meaning and grounding are sound.
4. **Pair contrast:** Compare the arms on their named `factorId`. V1 and most v2 pairs isolate one factor. `extensionv2.authority-guard-capacity` is an explicitly labeled compound contrast: it compares verified authority plus available guards with neither, and does not isolate authority from guard availability. Record whether the difference changed tone or choice where relevant, and whether unrelated dimensions stayed stable. Some pairs intentionally expect the same choice set or allow the same outcome; models need not manufacture a difference when both choices remain reasonable.
5. **Evidence and event integrity:** Check participant, event, source, game time, and observer knowledge. A world fact in `nativeFacts` is an offline oracle for reviewers and adapter checks. Never send hidden native facts to Qwen or D3. Build model context from the selected NPC's `npcKnowledge` and the normal whitelisted snapshot. A rumor remains attributed and uncertain. A direct witness may identify only what they actually observed.
6. **Mood and relationships:** Mood may respond to an accepted current event and cool only toward neutral with game time; use stable per-person variation and never reroll personality on read. Temporal mood projections require captured game time and mood `StateRevision`; an accepted native event must increment its causal state revision and invalidate stale projections. Do not count repeated recall, a reopened chat, a second callback, or a chat-sequence increment as a new event. Do not let mood cooldown decay affinity, trust, fear, resentment, or loyalty. Apply the existing appointment no-show consequence once from its existing receipt; future appraisal must consume that receipt rather than add a second penalty.

Suggested severity labels: **critical** for hidden-fact leakage, unauthorized option/effect, fabricated resource/payment/result, or applying an event to the wrong actor; **major** for unsupported certainty, promise-as-fulfillment, trust/affinity conflation, repeat application, or violating a clear scoped duty; **minor** for weak voice contrast or a defensible but less context-sensitive option. Keep the raw output, parsed output, selected ID, native validation result, reviewer note, model metadata, and corpus hash for every attempt. Do not retry, reroll, or remove a poor model response.

## Harness integration

Do not edit or run evaluation tools as part of this fixture-preparation task. Parent owns model calls and serial evaluation.

To adapt this bundle later:

1. Deep-merge each `arms[].contextPatch` into its pair's `commonInput`, using the stated merge rule. Produce a fresh isolated case for each arm. Do not carry one arm's model output or state into its pair mate.
2. Convert each arm into the current NPC Architecture case shape: preserve `input` fields, map `acceptableD3Choices` to `expected.allowedChoices`, keep option IDs/descriptions, and copy pair/factor IDs into case metadata. Save `expectedNativeEligibleOptionIds` separately; do not conflate native eligibility with semantic acceptability.
3. For model-facing payloads, remove the offline `nativeFacts` oracle. Supply only verified public/snapshot facts and the selected NPC's actor-known `npcKnowledge`, plus supported tools and options. Represent missing information as unknown; do not fill it from hidden fixtures.
4. Use D3's bounded option selection for choice review. Use the Qwen voice path for response wording and meaning. The current MoodEvaluation runner expects a mood `{reply,moodDelta}` response; these new cases do not define mood-delta targets and must not be forced into that protocol.
5. Keep the exact pair corpus and arm ordering fixed. Hash suite and code before inference; use fresh run directory and no retries. Run held-out paraphrases only as a separately versioned corpus after this set is frozen.
6. Preserve native validity results separately from Qwen/D3 judgments. A model choice or reply cannot authorize or report a native effect. Revalidate current state before any later action and accept completion only from a native receipt.

The current native context contract in `ConversationContextSnapshot` distinguishes `Unknown` from `Verified`, records fact source and observation time, and binds requests to actor/session/request revision, save epoch, archive head, and scene revision. Keep mood `StateRevision` distinct from `AcceptedTurnSequence`: temporal mood projections use captured game time and mood revision; chat sequence alone is not an event/state revision. Relationship and contract fields in these fixtures describe future contrasts, not current supported snapshot fields.


## Version 2 additions

The v2 file preserves v1 and adds six `extensionv2.*` pairs: a direct insult versus an attributed report, a direct family threat versus fictional/hypothetical dialogue, an insult with versus without established shared-joke context, the same message to the same native-person identity with an explicitly authored Noble rank but different stable status-attitude traits, a bounded compound comparison of explicit authority plus available local guards versus neither, and positive-growth-cap handling versus a witnessed severe loss. No rank is inferred from wealth, clothing, or eloquence; actual player rank must likewise be verified before status-based attitudes are applied. The family-threat and insult cases support social refusal or protection requests only where the synthetic evidence and future native adapter support them; they do not manufacture a crime report, guilt, unavailable guards, or quest flags. A genuinely alienated Main Quest speaker may permanently block access when actual native quest state permits that consequence, as the user accepts; never invent or flip a quest flag from dialogue appraisal alone.

The positive-cap fixture states policy qualitatively: no exact relationship deltas are prescribed, and the positive-growth cap cannot suppress an independently bounded negative loss. A future native-event adapter must increment the relevant native state revision for each accepted, deduplicated causal event; chat sequence or replayed appraisal is not a new event. Mood uses temporal `StateRevision` invalidation; relationship changes update their own revisions and remain independent of mood cooling. An appraisal may use only observations available to the NPC, never hidden cause/corpse/culprit truth. Existing appointment no-show penalties remain owned by their current native receipt and must not be applied a second time.

Version 2 is still a synthetic review contract. `expectedNativeEligibleOptionIds` are future-adapter oracle labels, not a statement that those choices or all underlying events exist in the current runtime. Preserve the raw model output and do not retry, reroll, or edit either frozen corpus after inference.
